# 值班台操作手册：实到核证与分场结账

本目录是值班员使用的应用层，只依赖 Node.js 内置模块。上游两个模拟服务见根目录 README。

```sh
npm run source      # 资料来源，默认 127.0.0.1:8700
npm run provider    # 闸机档与合作账台，默认 127.0.0.1:8701
```

本地状态默认写在 `./state/`（`desk.json` 为账台状态，`archives/` 留存下载的 gzip 原件），
可用环境变量 `STATE_DIR`、`SOURCE_URL`、`PROVIDER_URL` 覆盖。

## 核算口径（代码内强制，不依赖人工记忆）

1. **闸机档跟自然日走，结账跟营业日走。** 夜场跨午夜时按累计分钟落在多个自然日，
   每个 `(影院, 影厅, 自然日)` 分段都要封尾、序号连续，整场才可封。
2. **先放行、后权益、再去重。** 一条扫码先看是否实际放行且在场次窗口内，
   再看券在扫码现场时刻归属的权益是否适用本场，最后按票包去重。
3. **同票包只算一个观众。** 同一票包在一场用两项权益、或同券多次有效扫码，均只对应一人；
   未经授权的重复入场（换场后刷旧券、适用他场等）进拒绝清单，不会变成第二位观众。
4. **换场只迁一项权益。** 换场按扫码时刻生效：旧券在生效点后失效，新券经换场回执
   可追溯回原票包；同票包的其它权益不受影响，也不会把整张票包迁走。
5. **缺尾、断档、冲突三态分开，绝不按零人处理。**
   - 未封尾（含提前上传的档）：`unsealed`，现有放行可暂计但不能封账；
   - 序号缺失或来源索引里的放行在物理档找不到：`gap`；
   - 同一放行位内容不一致：`conflict`，此时不给实到数字，留人工核对。
6. **晚传文件不能替代事实判定。** 同一档案路径再投副本时，原件保留、旧登记标
   `superseded`，封尾以最新登记与完整序号同时核对为准。

## 命令序列

| 步骤 | 命令 | 说明 |
| --- | --- | --- |
| 1 | `npm run desk ingest [edition]` | 分页领取当期全部数据流并落本地；旧版保留合并 |
| 2 | `npm run desk archives <show>` | 按场次所涉影厅/自然日请档，gzip 原件逐份留盘 |
| 3 | `npm run desk reconcile <show>` | 核算状态、暂计实到、拒绝清单、分段问题与账行 |
| 4 | `npm run desk seal <show>` | 仅当证据齐时封账并留存快照，否则带原因拒绝 |
| 5 | `npm run desk amend <show> --line <账行>` | 已封场账行的更正，附权益增减与共同凭据 |
| 5′ | 同上加 `--provisional` | 新场未封时预提；合作台 409 则挂 `waiting-period` 等待 |
| 6 | `npm run desk receipts` | 读回合作台实际结论；待确认差额始终单独挂账 |
| 查询 | `npm run desk house <影院>` | 按影院列场次、进度、暂计人数、阻塞分段与账行 |
| 查询 | `npm run desk pass <票包>` | 按票包追每场扫码凭据、是否计入及待补分段 |
| 总览 | `npm run desk status` | 已领版本、已封场、更正工作项与档案登记 |

## 已封后到跨影院换场回执的处理

- 旧场与新场**分别**重算，各看各的实到依据和真实账期。
- 旧场从两个有效权益变一个时，独立观众数可能不变（同票包另有有效权益），
  更正件照常提交，`audienceDelta` 为 0、只修订凭据，不得凭一条撤销就扣合作款。
- 合作台允许一边先接更正（202）、另一边因当天未封拒绝（409）：
  409 的工作项保持等待，待新档封尾后用同一账行重新提交；未确认差额不与任何账互相抵清。
- 新场按其**有证的实到**重新作出结账决定，提交体含权益编号、独立观众增减与共同凭据。
